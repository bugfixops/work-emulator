# Converting one app to schema 2 (what was done for Currency, 2026-10-25)

Written for whoever (a later session of mine, or the student) converts the next app. Currency is the worked example: `graphs/Currency/graph_def.py`, `verification.csv`, `readme_notes.md`.
the reviewer's rules: labels come from the source and the emulator, never from tool coverage; every claim needs a source reference or is marked INFERRED; the generated graphs of the eight big apps may only be a cross-check, so those are rebuilt by hand.

1. **Back up, then make a build that works.** The v1 outputs of all 13 apps are in `archive/graphs_v1_2026-10-25/`. `python3 -I tools/build_graph.py graphs/<App> <prefix>` builds schema 2 from any old `graph_def.py` (legacy DEAD / FRAMEWORK_ONLY become UNREACHABLE with kind `unclassified`, gates get kind `unclassified`); the report lists what to classify under `TO CLASSIFY`.
2. **UNREACHABLE.** Replace `DEAD` and `FRAMEWORK_ONLY` by `UNREACHABLE = {method: (kind, reason, source_ref, 'SOURCE')}`. Kinds: no_trigger_in_app, branch_never_taken, framework_never_calls, closed_by_configuration (debug build, manifest, permission), closed_by_api_level. Re-read every call site (grep all source files); also grep for `SDK_INT`, `BuildConfig`, manifest flags that close a method on API 27 / the debug build.
3. **Gates.** List the distinct guards (`python3` over the JSON edges) and sort each into: program condition (leave), ENV (network, tls_chain, permission, hardware, other_app, system_event, time, other) or STATE (data, settings, account, file, session). Put the kinds in `ENV_KINDS_OF` / `STATE_KINDS_OF` (keyed by the exact text) and use the `EDIT(x)` hook to add gates that were only prose or a guard (Currency: widget placement, rotation, first-launch data). A tool run showing a method ran never removes a gate.
4. **Edge classes.** `CLASSIFY(x)` returns ('non_standard', via) for links made by a library or reflection (EventBus, ButterKnife, data binding, DI, Rx, XML-instantiated classes, `android:onClick`, intents resolved by action name); everything else keeps the default by kind. The report lists default-class edges whose text hints at a library (`REVIEW`); read them.
5. **Framework claims.** Replace every `FW-MEMORY` / `INFERRED` / `DYN` evidence by `FW-SRC android-8.1.0_r1:<dir>/<File>.java:<lines>` after reading the line in the AOSP source (`https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android-8.1.0_r1/...`; services under `services/core/java/com/android/server/...`; libraries from their GitHub tag). What cannot be checked (another app's behaviour, IME) stays INFERRED with the reason in the text.
6. **STRICT = True** once step 2-5 are done: anything unclassified becomes an error.
7. **Verify paths.** `python3 -I tools/verify_sample.py <App> 30`, then `tools/show_route.py <App> <methods> --dedupe` and read every step against the cited lines, including the guards. Run `tools/check_routes.py <App>` over all routes. Record rows in `graphs/<App>/verification.csv` (type label / edge / path; result correct / fixed / wrong / unclear; for a path the `edges` column repeats `route_edge_ids`). A wrong route is fixed in `graph_def.py` (Currency: `onActivityResult` split into `@OK` and `@CANCEL`) and recorded as `fixed`; the tool marks a verified path STALE when its route changes.
8. **README.** Write `graphs/<App>/readme_notes.md` (what changed, how the sample was chosen, what waits for a device, hazard candidates, limits) and run `python3 -I tools/gen_readme_v2.py <App>`.
9. **Test.** `python3 tools/tests/check_v2.py` checks the unconverted apps still build with the same paths.

What needs the emulator (API 27), not the source: delivery claims between apps or through the launcher, IME behaviour, and replaying the sampled paths (DEVICE confirmation). The CI set-up for API 27 emulator runs is in `work-emulator/`.

## Added after hash-checker (2026-10-25): checks that found real errors

- **`python3 -I tools/check_bytecode_lines.py <App> --emit`** (apps with bytecode-derived edges: hash-checker found 15 of 520 cited lines wrong). It checks that the line cited as `SRC File.java:N (bytecode)` contains the callee; paste the printed `FIX_LINES` into `EDIT`. Implicit `super()`, enum and Dagger-injector calls are skipped by design.
- **Several flavors / source sets:** `tools/show_route.py` now prefers `src/main` and the flavor named in `app/build/intermediates/javac/<flavor>Debug`; check `DATASET.txt` provenance and `BuildConfig.class` for the built flavor before judging a flavor-dependent label.
- **State no in-app action can create** (a preference nothing writes, a legacy value) = closed in the standard configuration. Remove the edge (hand edge: delete or skip it in the loop that creates it; automatic edge: `SUPPRESS`). A method only that edge reaches becomes UNREACHABLE `closed_by_configuration`; other methods stay REACHABLE through their other routes.
- **Data carried by the starting intent** (VIEW / SEND URI, launcher shortcut actions, extras read in `onCreate`) must be a context (`@XURI`, ...) from the entry edge down to the point where the data is read. Otherwise the best route starts with the plain launcher entry and then needs data the launcher start does not carry.
- **The builder skips an automatic call edge when any hand edge covers the same method pair** (`add_auto_edges`), and it copies automatic outgoing edges onto every hand-written context variant of a node. After adding context edges, rebuild and look for new "no path" errors: the plain edges for the covered pairs have to be written out by hand.
- **Guards of bytecode-derived edges are invisible** (first-launch checks, `if (x != null)` branches, "only for type X" dispatch, buffer-full conditions). Read the code around every step of a sampled route; add the guard text, or a STATE gate when a cheaper route without it exists (`EDIT` can set `guard` / `needs_state` by edge, keys of `STATE_KINDS_OF` must match the text).
- The sample of `verify_sample.py` depends on the graph: draw it again after the last fix, and log the final sample plus the methods already read.
- Without the androidx / ORMLite sources the lifecycle and library claims stay INFERRED (hash-checker: 453 of 529 labels INFERRED); that is expected, say it under "Limits".
- New tools: `tools/make_worklist.py <App>` (work list with per-app rules; never run it on an app whose list is in use), `tools/check_bytecode_lines.py`.

## Added after Omni-Notes (2026-10-25): what reading 33 routes found

Omni-Notes (hand-written, 1,456 methods, 3,803 edges): 30 of 33 read routes had an error. One was systematic, the rest each needed the source around one step.

- **The first-resume shortcut.** Page edges taken from `onResume` / a lambda straight into the list page skip what the first resume does (password check, `init()`, adding the fragment). 26 of 33 routes used one. Look at steps 1-9 of every route first; an edge into a page that is valid only after an earlier visit needs the STATE "resumed before in this process", and the cold start needs the explicit chain.
- **The route cost counts edges, not kinds**: fewest ENV-gated edges, then STATE-gated edges, then steps (`build_graph.py`, the Dijkstra loop); guards are ignored. A route can therefore pick an odd combination (an edge swipe instead of the FAB, the DashClock broadcast instead of the alarm). Both are valid when each step is; check each step, do not look for the "natural" route.
- **Debug-build short circuits.** `!isDebugBuild() && x()` never calls `x()` in the standard configuration; the bytecode edge to `x` must go (`sup`), and what only `x` leads to becomes closed_by_configuration. `grep -rn "isDebugBuild\|BuildConfig\.\(DEBUG\|BUILD_TYPE\|FLAVOR\)"` over the app sources once per app.
- **Split a method by how it is reached** when its branches depend on it: `importData@IMPORT` / `@LEGACY` (a flag from the action), `discard@EXIST` (note already has an id), `createAttachmentFromUri@PICK` (a content URI picked in another app, not the `file://` URI of a stored attachment). Pattern: `sup((m, callee))` for the plain pair, hand edges from each variant; the automatic outgoing edges of the plain node are copied to every variant, so every branch-specific callee needs the `sup` and one hand edge per variant. A page variant such as `S_DETAIL@CHECKLIST` holds both new and existing notes: use `NEED_EXISTING` on edges that need an id (Trash, Archive, Discard).
- **Early returns hide guards on everything after them** (`saveCategory` returns for an empty name; `onReceive` swallows exceptions): add one rule on `x['src']` that gives every later edge the guard. Same for statics read once per process (`fileLoggingEnabled == null`: first call only) and for `if (SDK_INT > 26)` blocks that also hold the class initialiser of a helper class.
- **Data origin.** When a route passes through a helper that takes a URI, an Intent or a Parcel, ask who made it: a note's stored attachment is `file://`, a picker result is `content://` (document URI of the picker's provider), a Parcel read in `onActivityResult` came from the activity that set it.
- **ENV texts are claims too.** Copy the condition from the code: the ideogram counter text said "Chinese, Japanese or Korean", the code names ja_JP, zh_CN, zh_TW. The `_env_kinds` regex is matched on the lower-cased text.
- **Hazard lists from memory.** A hazard that quotes a framework message must be backed by the source line (`SnoozeActivity`: `Activity.java:7003-7004, 7112-7123`); no FW-MEMORY in any file.
- **Labels of UNREACHABLE methods:** `tools/scan_unreachable.py <App> --all` (every mention) and the new `--callers` (bytecode callers outside the unreachable set; each one must be explained in its reason: Omni 5 of 254, hash-checker 4 of 22). Seven of 1,456 labels changed in Omni-Notes (5 to UNREACHABLE, 2 to REACHABLE).
- `tools/check_bytecode_lines.py` now handles local classes (`Outer$1Name`). Log generator pattern: `handoff/examples/make_vlog_omni_notes.py` style (assert every claim of a note against the graph with `has_edge(...)`, rebuild the first graph from the archived definitions to see which first-graph routes had which error).
- A sample's best route may change after a late fix; the log rows are written from the final build, and `edges` in a path row must equal the current route (otherwise STALE). Regenerate the log after the last change of `graph_def.py`.
